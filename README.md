# 선착순 번호표

## 1. 서비스 소개
- 대상 사용자: 선착순으로 순서를 정해야 하는 학과 학생과 행사 운영자
- 사용 상황: 간식 나눔, 동아리 면접 시간 선점, 발표 순서 정하기처럼 오픈하는 순간 접속이 몰리는 상황
- 해결하는 문제: 단체 대화방 선착순은 메시지가 동시에 올라와 순서 판정이 어렵다. 서버가 도착 순서대로 번호를 발급해 순서를 확정한다.

### 핵심 기능
| 기능 | 사용자 입력 | 결과 |
|---|---|---|
| 이벤트 만들기 | 이벤트 이름 | 이벤트 목록에 표시 |
| 번호표 뽑기 | 닉네임 | 도착 순서대로 번호 발급 |
| 실시간 대기 명단 | 이벤트 선택 | 1초마다 명단 갱신 |

## 2. AWS 구성도
```
브라우저 → EC2(서울 리전, Ubuntu) :8080 → Docker 컨테이너(Flask :5000)
```
- 요청 경로: 브라우저가 EC2 퍼블릭 IP의 8080 포트로 접속하면 Docker가 컨테이너의 5000 포트로 전달하고, Flask가 화면(static/index.html)과 API(/api/events) 응답을 만든다.
- 응답을 만드는 코드: `app.py`
  - `create_event()`: 이벤트 생성
  - `draw_ticket()`: 번호표 발급. `threading.Lock`으로 동시에 요청이 와도 번호가 겹치지 않게 처리
  - `get_tickets()`: 대기 명단 조회
- EC2 선택 이유: 수업에서 실습한 Docker Compose 구성을 그대로 실행할 수 있고, 컨테이너 1개 규모에는 ECS보다 설정이 단순하다.

### ELB·Auto Scaling 검토
- 적용 여부: 적용하지 않음
- 이유 1 (구조): 데이터를 서버 메모리에 저장하므로 서버가 2대가 되면 서버마다 번호가 따로 매겨진다. 적용하려면 번호 발급을 RDS나 DynamoDB 같은 공유 저장소로 옮겨야 한다.
- 이유 2 (비용): 접속은 오픈 직후 짧은 시간에만 몰린다. 로드 밸런서는 접속이 없을 때도 비용이 발생하므로 과제 규모에서는 단일 EC2가 적절하다.
- 실제 서비스라면: 공유 저장소로 전환한 뒤 ALB와 Auto Scaling(최소 1대, 최대 서버 수 제한)을 적용하고 예산 알림을 설정한다.

## 3. 실행·배포
### 준비 사항
- EC2 Ubuntu 인스턴스, 보안 그룹 인바운드 TCP 8080 허용
- Docker 설치: `curl -fsSL https://get.docker.com | sudo sh`

### 명령
```bash
git clone https://github.com/gunwoo-1/cc-chat-app.git
cd cc-chat-app
sudo docker compose up -d --build
curl localhost:8080/api/health
```
- 포트: 호스트 8080 → 컨테이너 5000
- 접속 주소: http://13.124.238.219:8080
### 로컬 실행
docker compose up -d --build
브라우저에서 http://localhost:8080 접속

  - EC2 사용자 데이터로 Docker 자동 설치가 실패해 직접 설치했다.
  - `index.html`이 `static/static/`에 들어간 것을 `git mv`로 수정했다.
