# 선착순 번호표

## 1. 서비스 소개
- 대상 사용자: 선착순으로 순서나 참여자를 정해야 하는 학과 학생과 행사 운영자
- 해결하려는 문제: 단체 대화방 선착순은 메시지가 동시에 올라와 순서 판정이 어렵고, 정원을 넘겨 받는 일이 생긴다. 서버가 도착 순서대로 번호를 발급하고 정원이 차면 자동으로 마감한다.
- 접속이 몰리는 시점: 간식 나눔, 동아리 면접 시간 선점처럼 이벤트를 여는 순간

### 핵심 기능
| 기능 | 사용자 입력 | 결과 |
|---|---|---|
| 이벤트 만들기 | 이벤트 이름, 정원 | 이벤트 목록에 "0/정원명"으로 표시 |
| 번호표 뽑기 | 닉네임 | 도착 순서대로 번호 발급, 정원이 차면 마감 |
| 실시간 대기 명단 | 이벤트 선택 | 1초마다 명단과 마감 여부 갱신 |

## 2. AWS 구성도
```
브라우저 → EC2(서울 리전, Ubuntu) :8080 → Docker 컨테이너(Flask :5000)
```
- 사용자 요청 경로: 브라우저가 EC2 퍼블릭 IP의 8080 포트로 접속한다. 보안 그룹이 8080을 허용하고, Docker가 컨테이너의 5000 포트로 전달하며, Flask가 응답한다.
- 사용한 AWS 서비스: EC2
  - 역할: Docker Compose로 웹서버 컨테이너를 실행하는 가상 서버
  - 선택 이유: 수업에서 실습한 Docker Compose 구성을 그대로 실행할 수 있고, 컨테이너 1개 규모에는 ECS보다 설정이 단순하다.
- 응답을 만드는 코드: `app.py`
  - `/` : 화면(`static/index.html`) 전달
  - `create_event()` : 이벤트 생성, 이름과 정원 검사
  - `draw_ticket()` : 번호표 발급. `threading.Lock` 안에서 중복 닉네임과 정원을 검사하고 번호를 매겨, 동시에 요청이 와도 번호가 겹치거나 정원을 넘지 않는다.
  - `get_tickets()` : 대기 명단 조회. `after` 값 이후에 생긴 번호표만 응답한다.

## 3. 실행·배포 방법
### 준비 사항
- Docker와 Docker Compose
- AWS 배포 시: EC2 Ubuntu 인스턴스, 보안 그룹 인바운드 TCP 8080 허용

### 로컬 실행
```bash
git clone https://github.com/gunwoo-1/cc-chat-app.git
cd cc-chat-app
docker compose up -d --build
```
브라우저에서 http://localhost:8080 접속

### AWS 배포 절차
1. EC2 인스턴스 생성 (서울 리전, Ubuntu), 보안 그룹에 TCP 8080 추가
2. PuTTY로 접속 후 Docker 설치
   ```bash
   curl -fsSL https://get.docker.com | sudo sh
   ```
3. 저장소를 내려받아 실행
   ```bash
   git clone https://github.com/gunwoo-1/cc-chat-app.git
   cd cc-chat-app
   sudo docker compose up -d --build
   curl localhost:8080/api/health
   ```
4. 코드 수정 후 재배포
   ```bash
   git pull
   sudo docker compose up -d --build
   ```

### 포트와 접속 주소
- 포트: 호스트 8080 → 컨테이너 5000
- 접속 주소: http://13.124.238.219:8080

## 4. 확장 검토
- ELB와 Auto Scaling 적용 여부: 적용하지 않음
- 판단 근거 1 (구조): 데이터를 서버 메모리에 저장한다. 서버가 2대가 되면 서버마다 번호와 정원을 따로 세므로, 번호가 겹치고 정원을 넘길 수 있다.
- 판단 근거 2 (비용): 접속은 이벤트를 여는 직후 짧은 시간에만 몰린다. 로드 밸런서는 접속이 없을 때도 비용이 발생해 과제 규모에서는 단일 EC2가 적절하다.
- 실제 서비스로 확장한다면
  1. 번호 발급과 정원 검사를 RDS나 DynamoDB 같은 공유 저장소로 옮긴다.
  2. ALB로 요청을 여러 서버에 나눈다.
  3. Auto Scaling에 최소 1대와 최대 서버 수를 정하고 예산 알림을 설정한다.
