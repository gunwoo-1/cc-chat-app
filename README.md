# 선착순 번호표

## 1. 서비스 소개
- 대상 사용자: 선착순으로 순서나 참여자를 정해야 하는 학과 학생과 행사 운영자
- 해결하려는 문제: 단체 대화방 선착순은 메시지가 동시에 올라와 순서 판정이 어렵고, 정원을 넘겨 받는 일이 생긴다. 서버가 도착 순서대로 밀리초 단위로 번호를 발급하고, 정원이 차거나 마감 시각이 되면 자동으로 마감한다.
- 접속이 몰리는 시점: 간식 나눔, 동아리 면접 시간 선점처럼 이벤트가 오픈되는 순간

### 핵심 기능
| 기능 | 사용자 입력 | 결과 |
|---|---|---|
| 이벤트 만들기 | 이름, 정원, 오픈 시각, 마감 시각 | 목록에 카드로 표시 (모집 중 / 오픈 예정 / 마감 임박 / 마감) |
| 번호표 뽑기 | 닉네임 | 서버 도착 순서대로 번호 발급, 정원·시간 조건에 따라 마감 |
| 실시간 대기 명단 | 이벤트 선택 | 다른 사용자가 뽑는 즉시 명단과 남은 자리 갱신 |

### 추가 기능
| 기능 | 내용 |
|---|---|
| 오픈 예약 | 지금 / 1·3·5분 후 오픈. 오픈 전에는 카운트다운이 표시되고 뽑기 버튼이 잠기며, 서버도 오픈 전 요청을 거부(403) |
| 마감 시각 | 마감 없음 / 오픈 후 10·30·60분. 정원이 차거나 마감 시각이 되면 마감되고, 시각이 지난 요청은 서버에서 거부 |
| 마감 기록 | 정원이 찬 경우 "오픈 후 N.NN초 만에 마감" 표시, 상단에 최단 마감 기록 표시 |
| 공유 링크 | `주소/#event-번호` 링크를 복사해 공유하면 해당 이벤트로 바로 입장 |
| 번호표 기억 | 새로고침하거나 다시 들어와도 내가 받은 번호표 유지 (브라우저 localStorage) |
| 화면 | 대시보드형 디자인, 실시간 통계(전체·모집 중·발급 수·최단 마감), PC 2단 / 모바일 1단 |
| 뒤로 가기 | 이벤트 화면에서 브라우저 뒤로 가기를 누르면 사이트를 벗어나지 않고 목록으로 이동 |

## 2. AWS 구성도
```
브라우저 → EC2(서울 리전, Ubuntu) :8080 → Docker 컨테이너(gunicorn + Flask :5000)
```
- 사용자 요청 경로: 브라우저가 EC2 퍼블릭 IP의 8080 포트로 접속한다. 보안 그룹이 8080을 허용하고, Docker가 컨테이너의 5000 포트로 전달하며, gunicorn이 Flask 앱을 실행해 응답한다.
- 사용한 AWS 서비스: EC2
  - 역할: Docker Compose로 웹서버 컨테이너를 실행하는 가상 서버
  - 선택 이유: 수업에서 실습한 Docker Compose 구성을 그대로 실행할 수 있고, 컨테이너 1개 규모에는 ECS보다 설정이 단순하다.
- 응답을 만드는 코드: `app.py`
  - `/` : 화면(`static/index.html`) 전달
  - `create_event()` : 이벤트 생성. 이름·정원·오픈·마감 시각 검사
  - `draw_ticket()` : 번호표 발급. lock 안에서 오픈 시각 → 마감 시각 → 중복 닉네임 → 정원 순서로 검사하고 번호를 매겨, 동시에 요청이 와도 번호가 겹치거나 정원을 넘지 않는다.
  - `get_tickets()` : 대기 명단 조회 (롱 폴링)
  - `list_events()` : 이벤트 목록 조회 (롱 폴링, 데이터 버전 비교)

## 3. 실행·배포 방법
### 준비 사항
- Docker와 Docker Compose
- AWS 배포 시: EC2 Ubuntu 인스턴스, 보안 그룹 인바운드 TCP 8080 허용

### 파일 구성
| 파일 | 역할 |
|---|---|
| `app.py` | Flask 서버 (API와 화면 전달) |
| `static/index.html` | 화면 (HTML, CSS, JavaScript) |
| `requirements.txt` | 파이썬 의존성 (flask, gunicorn) |
| `Dockerfile` | 이미지 빌드, gunicorn으로 실행 |
| `compose.yaml` | 포트 연결(8080→5000), 자동 재시작 |

### 로컬 실행
```bash
git clone https://github.com/gunwoo-1/cc-chat-app.git
cd cc-chat-app
docker compose up -d --build
```
브라우저에서 http://localhost:8080 접속

### AWS 배포 절차
1. EC2 인스턴스 생성 (서울 리전, Ubuntu), 보안 그룹에 TCP 8080 추가
2. PuTTY로 접속 후 Docker 설치
   ```bash
   curl -fsSL https://get.docker.com | sudo sh
   ```
3. 저장소를 내려받아 실행
   ```bash
   git clone https://github.com/gunwoo-1/cc-chat-app.git
   cd cc-chat-app
   sudo docker compose up -d --build
   curl localhost:8080/api/health
   ```
4. 코드 수정 후 재배포
   ```bash
   git pull
   sudo docker compose up -d --build
   ```

### 포트와 접속 주소
- 포트: 호스트 8080 → 컨테이너 5000
- 접속 주소: http://13.124.238.219:8080

## 4. 효율 개선
| 항목 | 개선 전 | 개선 후 | 이유 |
|---|---|---|---|
| 실시간 갱신 | 1초마다 요청 (사용자 1명당 분당 약 120회) | 롱 폴링 (`threading.Condition`) | 새 번호표가 생길 때만 응답하고, 변화가 없으면 25초마다 1회. 요청은 분당 2~3회로 줄고 반영은 즉시 |
| 목록 갱신 | 매번 전체 다시 그림 | 데이터 버전 번호 비교 | 바뀐 경우에만 다시 그림. 카운트다운은 서버 시각 차이를 보정해 화면에서 계산 |
| 중복 검사 | 리스트 순회 O(n) | set O(1) | 정원이 많아도 검사 속도가 같음 |
| 실행 서버 | Flask 개발 서버 | gunicorn (워커 1, 스레드 100) | 운영용 서버. 데이터가 메모리에 있어 워커는 1개, 대기 중인 접속은 스레드로 처리 |
| 이미지 빌드 | 매번 Flask 재설치 | requirements.txt 먼저 설치 | 코드만 바뀌면 설치 단계를 캐시로 재사용해 빌드가 빨라짐 |

- 오픈·마감 시각 검사는 화면뿐 아니라 서버(`draw_ticket`)에서도 한다. 화면 버튼만 막으면 개발자 도구로 요청을 직접 보내 새치기할 수 있기 때문이다.

## 5. 확장 검토
- ELB와 Auto Scaling 적용 여부: 적용하지 않음
- 판단 근거 1 (구조): 데이터를 서버 메모리에 저장한다. 서버가 2대가 되면 서버마다 번호와 정원을 따로 세므로 번호가 겹치고 정원을 넘길 수 있다.
- 판단 근거 2 (비용): 접속은 오픈 직후 짧은 시간에만 몰린다. 로드 밸런서는 접속이 없을 때도 비용이 발생해 과제 규모에서는 단일 EC2가 적절하다.
- 판단 근거 3 (현재 한계): 롱 폴링 대기 접속은 스레드 1개씩 사용하므로 스레드 수(100)가 동시 접속 상한이다.
- 실제 서비스로 확장한다면
  1. 번호 발급·정원·마감 검사를 Redis, RDS, DynamoDB 같은 공유 저장소로 옮긴다.
  2. ALB로 요청을 여러 서버에 나눈다.
  3. Auto Scaling에 최소 1대와 최대 서버 수를 정하고 예산 알림을 설정한다.
